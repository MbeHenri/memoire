    \section{Contexte et description de l'article}
    Dans le but d'aider à la recherche des médicaments basées sur les produits naturelles, plusieurs solutions récemment proposées utilisent des étapes d'alignements de fonctionnalités à l'instar du processus FBMN (Featured-based Molecular Networking) (présent sur la figure \ref{fig:fbmn}) qui rendent coûteux l'ajout de nouveaux exemples d'extraits.
    De plus, aucune d'elle ne propose de moyen d'analyse permettant de correspondre efficacement des exemples avec les données métabolomiques et métadonnées de sources externes.
    Dans l'objectif de répondre à ces limites les auteurs ont proposés dans l'article de référence \cite{gaudry2023sample}, un framework ENPKG(Experimental Natural Products Knowledge Graph)inspiré de LOTUS \cite{rutz2021lotus}, basé sur les graphes de connaissances et centré sur l'exemple, qui sera sujet de ce document.
 
    Comme informations liées à l'article, on a:
    \begin{itemize}
        \item \textbf{titre} :{A Sample-Centric and Knowledge-Driven Computational Framework for Natural Products Drug Discovery}
        \item \textbf{auteurs}: {Gaudry, Arnaud and Pagni, Marco and Mehl, Florence and Moretti, S{\'e}bastien and Quiros-Guerrero, Luis-Manuel and Rutz, Adriano and Kaiser, Marcel and Marcourt, Laurence and Queiroz, Emerson Ferreira and Ioset, Jean-Robert and others}
        \item \textbf{année}: {2023}

    \section{Workflow}
    Comme décrit plus haut, il était question pour les auteurs de proposer un framework qui permettrait de correspondre au mieux les exemples de leur système
    aux données et métadonnées métabolomiques de systèmes extérieurs. Le système obtenu dont workflow est présent sur la figure \ref{fig:enpkg}, permet d'introduire progressivement de nouveaux exemples.
    Pour etre ajouter dans le système, les exemples nécessite un formatage en dossier contenant :
    \begin{itemize}
        \item un dossier pour les fichiers pour le réseau moléculaire de l'extrait (de la liste de spectres MS2 de l'exemple)
        \item un dossier pour les notations "In Silico"
        \item un dossier pour la résolution de typologie de l'exemple sur le graphe de connaissance
        \item un dossier pour les annotations SIRIUS
    \end{itemize}
    
    Ces formats d'exemples seront introduits par la suite dans le graphe de connaissance globale et sauvegardés dans une base de données \textbf{zenodo}.
    Ainsi pour contenir le graphe de connaissance global, on utilise la base de données de graphe  \textbf{\href{https://graphdb.ontotext.com}{GRAPHDB}}
	qui pourra être sujet de requête pour obtenir des informations globales internes comme externes. Cela à cause du fait que le graphe intègre des liaisons aux plateformes publiques externes telles que GNPS et ChEMBL respectant une certaine structure.
    
    \begin{figure}
        \centering
        \includegraphics[width = \linewidth]{Images/enpkg.png}
        \caption{Workflow du framework ENPKG \cite{gaudry2023sample}}
        \label{fig:enpkg}
    \end{figure}

	On peut segmenter le workflow en trois grandes parties qui se suivent
    
	\subsection{Acquisition des données}
    	Cette étape consiste à obtenir les données spectrales MS2 par chromatographie liquide LC-MS/MS des différents extraits de base. Ces spectres par exemple seront par la suite introduits dans le dépôt MASSIVE et utilisés pour le graphe de connaissance après prétraitement.

	\subsection{Prétraitement des exemples}
    	Cette étape consiste à prétraiter les exemples pour être introduit dans le dépôt MASSIVE et utilisés pour être introduit dans le graphe de connaissance après intégration.
    	Comme décrit brièvement plus haut, les exemples sont transformés en des dossiers correspondants d'intégration après ajout de métadonnées.

	\subsection{Intégration des exemples}
	C'est en cette phase qu'on introduit les exemples de base ou de nouvelles dans le graphe globale de connaissance.  Les dossiers d'exemples sont analysés et attachés aux bases de données WIKIDATA de références et ChEBML de molécules bioactives. Puis de ces dossiers sont générés les sous graphes à intégrer dans le graphe globale après introduction dans la base “zenodo".
    
	\section{Conclusion}
	En somme, il était question de présenter, tel que nous avons perçu le workflow ENPKG donné par les auteurs qui pourrait être très utile à la découverte de médicaments.
    Ce framework permet d'exploiter les connaissances externes (données et métadonnées externes) au système pour accélérer l'exploration des extraits du système (en effectuant des requêtes sur la base de données de graphe globale) et d’ajouter efficacement des exemples futurs.
	Ainsi d'après le workflow, il pourrait être intéressant d'intégrer l'utilisation des données RMN (1D et 2D) à l'instar de construire des réseaux moléculaires unifiés MS-RMN pour chacun des exemples d'extraits.
    Malgré les objectifs de sa création atteints, il a un inconvéniant majeur qui est l’utilisation d’un langage d'interrogation qui n’est pas facilement accessible par les utilisateurs finaux que sont les biologistes.
    Cela permet de se pencher sur la question de comment rendre moins complexe l’accès aux données par un utilisateur final? Comment construire automatiquement les requêtes sur la base de demandes textuelles des utilisateurs finaux?
